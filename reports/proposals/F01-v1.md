# F01 v1：请求内 prefix KV 缓存，与 level 0 合并构建

用户随后以“按照这个实现吧”批准本版本及新增最多 3 GPU 小时预算。

## 1. 功能与范围

在独立 serving 系统中，一次请求只计算一次 prefix 的 Transformer 表示，保存每个网络 block 的 K/V，后续 concept levels 仅更新 target 位置。仍使用同一模型、相同精度、相同生成顺序。本轮是单 GPU 请求内缓存，不训练模型、不做跨请求共享、不实现多 GPU 传输或新 kernel。

对应 kickoff checklist 的 F01；与已完成的 F11（单卡 A/B 分组）组合验证。当前 serving 基线：`6254fb38be95b18ee905ae6c11f86efb312160d1`；固定 upstream：`c70274273f489abc73832b2b98584a8483b6b203`。

## 2. 已确认的问题与实际例子

`src/ncm_serving/engine.py::_step` 在 level > 0 时调用 upstream `_decode_level_logits`。上游 `models/next_concept.py:501` 先拼接 prefix 与当前 target，再循环执行全部 Transformer blocks。prefix 的词嵌入已在 submit 缓存，但每层网络的 QKV、attention、输出投影和 MLP 仍逐 concept level 重算。

现有 probe 原始记录（工作区 `worktrees/f00/reports/raw/F00-v1/review-20261023/profile-validation.json`）六种配置均观测到以下 stack 输入长度：

| 路径 | level 0 | A：levels 1–4 | B：levels 5–10 | 累计 |
| --- | --- | --- | --- | --- |
| 当前 eager（已观测） | 96 | 100,104,110,116 | 122,128,136,144,152,160 | 1368 |
| 本提案缓存（预期） | 96 | 4,8,14,20 | 26,32,40,48,56,64 | 408 |

每个 block 少处理 960 个位置，减少 70.18%。这是每条 effective batch row 的位置计数；整网还要乘 12 blocks，CFG=1 的 effective batch 为原始 batch 的两倍。level 0 的一个 code 来自 prefix hidden state，不额外增加一个 target 位置。

408 不表示后续 attention 只看 target：每层 target query 仍访问 `96 + L` 个 keys；prefix K/V 每轮仍需读取。仅 QKV/MLP 等逐位置工作量可用 1368/408 作粗略比例，**不能据此承诺 3.35 倍端到端加速**。最终 tokenizer decoder、采样、交接、内存复制和 CPU 开销仍存在。

## 3. 已有 KV 路径为什么不能直接打开

上游并非没有缓存实现，`generate(use_kv_cache=True)` 已存在，但固定版本有三个问题：

1. `next_concept.py:630–657`：level 0 先跑 prefix stack，随后开启缓存再跑一次。即使修好 mask，当前位置总数也是 `96 + 96 + 312 = 504`，不是 408。
2. `next_concept.py:655,683`：缓存 prefill 与 target 的 mask 均为零，漏加 `_pbias`。实际 padding keys 会参与注意力，CFG null 分支尤其受影响。之前已有 `test_old_kv_path_exposes_padding_key` 的最小回归证据。
3. `common.py:74,113–118`：缓存存储于共享 attention module 的 mutable fields。上游完整 generate 会在每轮恢复 prefix-only 缓存，避免跨 level 追加；但直接搬到可交错的 serving 请求中，需要外置状态，不能把 module 全局缓存当请求缓存。

本提案在 serving adapter 内实现语义正确的缓存路径，保留 upstream checkout 不变；不把旧 KV 路径当合格性能基线。

## 4. 依据与可复用条件

直接依据为固定版本 [NCM eager 与 KV 实现](https://github.com/HazyResearch/ncm/blob/c70274273f489abc73832b2b98584a8483b6b203/models/next_concept.py#L501) 以及 [attention 与 Block 实现](https://github.com/HazyResearch/ncm/blob/c70274273f489abc73832b2b98584a8483b6b203/models/common.py#L87)。不是新算法或研究首创声明。

eager mask 禁止 prefix query 看 target，允许 prefix 内部双向 attention；LayerNorm、MLP 和 RoPE 不混合不同位置。因此在 eval 模式、相同输入/权重/mask/位置配置下，逐 block 的 prefix hidden state 与当前 level 无关，可按网络层归纳复用。只读 final-prefix hidden 或只缓存最后一个 block 都不够，必须保留每个 block 的 K/V。

实现使用 [PyTorch 2.6 SDPA](https://docs.pytorch.org/docs/2.6/generated/torch.nn.functional.scaled_dot_product_attention.html)：显式 additive mask、`is_causal=False`、`dropout_p=0.0`。K/V 拼接后做一次联合 softmax；不把 prefix/target 分别归一化。改变张量形状可能改变浮点结果或后端选择，所以数值与最终输出必须实际验证。

## 5. 实现设计

### 5.1 level 0 同时 prefill 和建缓存

新增显式、无 module 缓存副作用的 block/attention adapter。直接复用原网络参数与 norm/MLP 模块，严格保持 `ln_1 → attention → residual → ln_2 → MLP → residual` 顺序；v1 只支持已核验的 WMT14 普通 residual block/MHA 配置，遇到额外 parallel_block、normformer、layerscale、rezero 或 GQA 变体明确拒绝缓存模式。

在 level 0 的唯一 prefix stack 中，每个 block：

1. 对该 block 的 prefix 输入归一化、QKV projection，执行原 QK norm。
2. 对 Q/K 施加 prefix 位置 `0..95` 的 RoPE。
3. 保存该 block 的 `K_prefix_rotated` 和 `V_prefix`，形状均为 `[B_effective, 12, 96, 64]`。
4. 使用正确 prefix padding bias 完成双向 prefix attention、residual 和 MLP，向下一个 block 传 hidden。

最后仍执行原 `ln_f`、`_level0_slice`、`lm_head_l0` 和采样。一次 stack 同时产出 level 0 code 与全部 prefix KV。

### 5.2 后续 levels 只执行 target stack

latent 更新、upsample、level embedding 和 head 索引保持原样。对每个 block 的 target 输入，仅计算长度 L 的 QKV；对 target Q/K 使用该 level RoPE 表的 `[P:P+L]` 切片（实际位置重置为 `0..L-1`，不是 `P..P+L-1`）。

联合 attention 的 `Q=[B_eff,H,L,D]`，`K/V=[prefix_K/V; current_target_K/V]`，key 长度 `P+L`。mask 可由 `[B_eff,1,1,P+L]` 广播：prefix PAD 为负无穷，其余为零。target 看完整有效 prefix 与当前 level 全部 target，不是 causal attention。

完成 target residual/MLP 后继续下一个 block。current-level K/V 只活在这次 block 调用内；prefix 缓存始终长度 P，不写回 target K/V，不二次旋转 prefix K。最后沿用原 head、CFG 混合、采样及 RNG 保存。

### 5.3 状态与生命周期

`LevelState` 增加可选 `prefix_kv`，包含 12 组 K/V；绑定请求代次、完整 prefix/padding、模型权重与配置指纹、dtype/device、布局、RoPE 配置和 CFG 分支布局。无跨请求查找/命中，不允许仅凭共同文本前缀共享。

A→B 在现有 handoff 边界克隆缓存，旧状态失效并解除旧缓存引用，B 使用完整快照；先保留可审计的复制语义，将复制成本计入 E2E。完成、取消、异常时清除执行器及 scheduler 终态记录持有的 KV 引用，避免 requests 字典保留 GPU cache。测试外部引用和 allocator reserved 的区别；不得声称删除引用即归还全部 CUDA reserved memory。

## 7. 正确性约束与门槛

FP32、TF32 off、eval/no_grad，原始生成长度和采样设置固定。有效 prefix 长度可不同，保留固定 P=96 布局；v1 不做 padding 压缩。CFG 条件/null 两半各有独立 mask 和对应 cache，保持原 batch 顺序。

浮点中间量（逐 block K/V、target hidden、logits、最终 latent）：`abs(actual-reference) <= 1e-4 + 1e-3*abs(reference)`；额外记录最大绝对误差和参考量接近零时的相对误差定义。独立 float64 attention/RoPE oracle 使用 `atol=1e-5, rtol=1e-4`。

greedy/现有 top-k=1 条件下全部 codes、最终 IDs、文本必须精确一致；容差通过不能掩盖离散不一致。随机小模型路径保留相同 RNG 状态，比较 logits/概率与输出、交错前后 RNG；不把少量同 seed 文本一致声称为所有采样分布已统计验收。

## 9. Benchmark 计划

三路径：U0 原生 eager；E0 当前 serving eager；K1 相同 serving 加 prefix cache。U0/E0/K1 使用同样无梯度、dtype、采样、输入顺序及输出边界；旧 F00 数据无效，不作数值对照。旧上游 KV 缺陷只作 debug，不当速度基线。

- B01：RTX 4060，B=1/4/8、CFG=0/1；每路径每格 5 独立窗口、每窗 16 batches，单独 profile。分开记录 prefix prefill、各 level attention/MLP、采样、latent、最终 decoder、handoff 和 cache 字节；CPU enqueue 与 CUDA events 分离，嵌套区间不相加。
- B03：同六格、三路径、每格 5 窗 ×1024 样本。CPU 预 tokenized tensor 到 CPU final IDs，全生成和 handoff 在边界内；文本解码、评分、调试 codes D2H 在边界外。scheduler 的输入准备和终态清理采用相同规则且记录时间。模型加载/模型指纹单列；cache 每请求建立，严禁预先建好后只报 target 耗时。
- 每个 worker 独立加载，warmup 至相邻 5-batch 中位数差异 ≤5%，至少 10 batches、最多 50；未稳定不开始正式窗。三路径配对交错，并按窗口轮换顺序。运行源码/配置冻结并保存 diff/hash；运行中变化立即停止。正式计时关闭 trace/hooks，profile 另跑；峰值 allocated/reserved 分开。
- 报告 batch latency p50/p95、req/s、实际输出 token/s、5 窗中位数/IQR/CV、每窗 paired ratio，以及 cache/handoff 增量显存。不宣称此离线样本量证明线上 p99/SLO；无新增 serving/load 或 multi-GPU benchmark。

## 10. 成功与停止标准

正确性通过、逐 block 408 位置计数成立，才算缓存功能实现成功。性能每格要求 CV≤10%；缓存相对 E0 的配对时延改善中位数 ≥5%，且五窗方向一致，才标该格有稳定收益；同时报告相对 U0 的值。否则 NO_GAIN 或 NO_STABLE_MEASUREMENT，不用理论位置比替代实测。

任意离散不一致、缓存跨请求污染、资源上限、源码变化即停止对应验收；保留失败。B=8 OOM 可作为容量结果，但不虚构该格性能；B=1/4 必需项失败则整体 BLOCKED。不得放宽容差、降精度或减少样本伪装完成。

## 11. 新预算请求

原 F00 用时账本不完整，追加 15 分钟仅授权正确性且已有消耗；本提案不假定其余额可覆盖新性能实验。

- 新增下载：0；复用现有 venv、固定 NCM checkout、WMT14 checkpoint/data/tokenizer。
- 新增磁盘上限 256 MiB，整个工作区仍受 20 GiB 上限约束。
- 单 RTX 4060，GPU 全进程墙钟预计 120–180 分钟，请求新硬上限 **3 GPU 小时**，每个子进程启动/结束和剩余预算独立记账，超时杀停。预算不足时保留 partial/BLOCKED，不自动缩减矩阵。
- prefix KV 理论量 `2 ×12 ×B_eff ×96 ×768 ×4 bytes`：6.75 MiB/B_eff；B=8、CFG=1 为 108 MiB，仅 cache。handoff clone 可暂时翻倍到 216 MiB，另有 activation/临时拼接/decoder；实际峰值待测。启动前检查空闲显存并预留约 1 GiB，OOM 停止而不重配精度。
- 现有硬件，无云费用；不申请新卡，不使用子 agent。

## 12. 风险与后续顺序

张量形状变化可能改变 GEMM/SDPA 数值与选择的 kernel；缓存减少计算却增加常驻显存、读取和拼接，实际收益可能低于预期。若全量离散对齐失败，保存首个失败层/输入并定位，不自动接受质量小幅变化。

F11 的 A/B 划分仍保持 split=5 验证；先取得缓存后的 profile 再决定新的分界或是否需要阶段分离。缓存可能改变短/长组相对成本，现有分组不能据此视为最优。跨 GPU 时 cache 的传输/重建策略另立提案。
