# F01 v1：请求内 prefix KV 缓存结果

状态：**VALIDATING**。本文件随验收更新，未完成项不视为通过。

实现位于独立 serving 仓库分支 `codex/f01-prefix-kv`。上游固定为
`c70274273f489abc73832b2b98584a8483b6b203`，没有修改或复制完整模型。
默认保持 eager；Python `prefix_cache=True`、CLI `--prefix-cache` 启用缓存。

## 实现

level 0 的一次 prefix forward 同时产出 level 0 code 和每个 block 的
prefix K/V。K 保存于 QK norm、RoPE 之后；后续 levels 只投影 target，
联合访问 prefix 和当前 level 的 keys。prefix PAD 继续屏蔽，target
位置每个 level 从零开始，临时 target K/V 不写回持久缓存。

缓存属于请求状态；A/B 交接克隆缓存并清除旧状态引用。完成、取消、
执行异常释放缓存，scheduler 终态记录解除 state 引用。旧状态和外来
状态不能恢复执行。缓存模式限定 FP32 MHA 普通 residual block，拒绝
parallel block、NormFormer、LayerScale、ReZero、GQA 等未验证配置。

## 正确性

| 检查 | 结果 |
| --- | --- |
| CPU 实际小模型：2 split × 2 CFG × greedy/stochastic | 8 个组合 codes/IDs 精确一致，latent 在固定容差内，外部 RNG 不变 |
| 独立 float64 dense attention/complex RoPE oracle | 通过；故意去掉 PAD mask、移动 target 位置、二次旋转 prefix K 均被检查发现 |
| 生命周期与请求隔离 | 不同 prefix/seed/CFG 请求交错、100 次 CPU 取消、直接 API 与 scheduler 异常释放通过 |
| GPU 10 split × 2 CFG，B=4 | 20/20 边界与原生 eager codes/IDs 精确一致 |
| GPU 逐 block K/V、target hidden、logits | 两 CFG 共 814 项比较通过 `atol=1e-4, rtol=1e-3`；最大绝对误差约 2.29e-4 |
| GPU QKV 和 MLP 输入 hooks | 12 个 block 均为 `[96,4,8,14,20,26,32,40,48,56,64]`，合计 408 |
| GPU 连续 20 次交接/取消 | 活跃缓存归零；稳定段 allocated 固定为 1,137,245,696 bytes，reserved 单独记录 |
| WMT14 全量 CFG=0 | 3003/3003 codes、IDs、文本与新 eager 及历史原生结果一致 |
| WMT14 全量 CFG=1 | 3003/3003 codes、IDs、文本与新 eager 及历史原生结果一致 |

位置数从 1368 降至 408，减少 70.18%；这是逐 block、每条 effective
batch row 的计算位置数，不能当作端到端加速倍数。后续 target 仍访问
`96 + L` 个 keys。

原始正确性证据：`reports/raw/F01-v1/quality-01.json`、
`quality-cfg0.json`、`quality-cfg1.json`。原始 JSON
中的输出 SHA-256 对紧凑 JSON 编码计算；与历史记录对比时，另按历史
相同的 signed int32 little-endian 格式计算，避免混淆编码差异。

| CFG | 样本 | BLEU | chrF |
| --- | ---: | ---: | ---: |
| 0 | 3003 | 21.720218 | 49.564860 |
| 1 | 3003 | 22.946409 | 51.515977 |

全量质量之后仅为入口增加了拒绝 autocast 的保护，不改变已验证 FP32
路径的计算；该入口保护另有 CPU 测试。正式矩阵前再次进行六配置原生
对照及 instrumentation 透明性检查。每次 GPU worker 的源码哈希均保留。
